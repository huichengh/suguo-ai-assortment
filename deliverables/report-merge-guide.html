一、本文件的性质与范围

本稿是《AI驱动的社区商超智能选品与品类优化研究》场景分析报告第三、四、五、六章的替换稿。使用方式为整章替换，而非逐段修改——原因是本稿依据的工程事实已从“单文件 HTML 前端＋自研后台”的原型，切换为“React 18＋TypeScript 前端＋FastAPI 后端”的完整工程化版本“苏果智选”v1.0，两套事实的差异贯穿架构、接口、数据与全部实证数值，逐段修改的改动量大于整章替换。

本稿保留原报告的章节框架：第三章 3.1—3.3、第四章 4.1—4.5、第五章 5.1—5.5、第六章 6.1—6.3 的二级结构与次序完全一致。在此前提下有四类贴合实际的调整，均需在合并时知悉。

其一，三级条目有两处标题微调。4.3.5 由“前后端双实现与一致性验证”改为“前后端职责边界与一致性验证”（新工程为单一后端，不存在双实现）；5.5.1 由“五层自动化验证体系”改为“自动化验证体系”（新工程为 pytest 单元测试体系）；5.4.3 由“局限说明”改为“预测精度的说明：为何不报告精度指标”，标题与内容一致化。

其二，第三章 3.2 下增加两个三级条目（3.2.6、3.2.7）。原框架 3.2 下设五个条目（3.2.1—3.2.5）。平台建设过程中形成的两条贯穿性约束——“数据不足时拒绝输出”与“高影响建议必须人工审批”——在原框架中没有承载位置，故补为 3.2.6 与 3.2.7。这两节内容被后续章节多处交叉引用（3.2.6 被 4.4.5、5.5.3 引用；3.2.7 被 4.2.5、5.5.4、6.3 引用），删除后文将失去依据，因此建议保留。

其三，正文前增加一节“数据性质与来源说明”。该节是数据免责声明的正文版本，性质对应原文附录 B 的“数据免责声明”。合并时建议将其移至报告前置部分（摘要与目录之后、第一章之前），或与附录 B 的免责声明合并；若保留在第三章之前，其标题为一级标题，会使目录中出现一个未编号条目，需相应调整目录。

其四，正文体裁已按“场景分析报告”规范统一。具体包括：取消原有的彩色提示框与四级标题，一律改为段落叙述；在关键定量段落后补“数据来源：……”独立引注，与原文的引注体例保持一致；清除全部版本比较与开发过程叙述（“与前一版修订稿的差异”“本次撰写过程中”“本轮新增”等），改为报告正文应有的表述。

四、合并时的五点提醒

第一，务必核对“数据不足”相关的表述是否被其他章节弱化。本稿在 3.2.6、4.2.4、4.4.5、5.5.3 四处反复强调平台的数据边界（SKU 级数据为 0、会员数据缺失、自有品牌对照数据缺失）。若报告的其他章节使用了“全面覆盖”“精准预测”这类表述，会与本章产生直接矛盾，必须一并修正。这一组表述是本稿最需要保护的严谨性。

第二，5.3.3 的评分口径校准过程建议保留，不要删减。该节完整记录了健康度算法早期实现中 240—938 分越界、7 品类全五星、子分出现负值的问题，以及根因（Min-Max 分子分母口径不一致）与修复方案。删掉它会让第五章变成一份“一次就写对”的报告，反而降低可信度；保留它则同时展示三件事：研究过程具备复现与核查能力、有测试体系、有如实披露的态度。我们判断这在评审中属于加分项而非减分项。

第三，全部数值已本地实测复核，但请勿改动其中任何一个数字。本稿第三至六章出现的每一个具体数值——包括健康度子分、关联规则的支持度／置信度／提升度、预测值、环比变化率、表行数、代码行数——均取自平台 SQLite 演示库的实读结果或后端算法函数的实算输出，并已逐项复核。原始数据包与复核脚本随交付件一并提供。若因排版调整而误改某个数字，将破坏全文的数一致性；如需更新数据，应重新执行品类健康度重算接口、关联规则重算接口、预测运行接口三个接口后整体替换，而非手工修改。

第四，本稿在体裁上是“场景分析报告”正文，请勿在合并时引入版本比较或开发过程叙述。本稿已清除“与前一版相比”“本次修订”“本轮新增”等表述，并在关键定量段落后补入“数据来源：……”引注。若在合并过程中重新加入此类内容，会与全稿体裁不一致。所有工作性说明均集中在本附录，合并时应整体移除。

第五，第三章 3.1／3.2 与 3.3 的分工不同，合并时不要回填。本稿 3.1 与 3.2 为纯理论部分，只讲框架、理论内涵与设计原则，不出现接口路径、页面路由、数据表行数与实测数值；相关内容全部落在第四章（设计与实现）与第五章（实证）。但 3.3「痛点到AI解法的映射」是有意保留平台内容的——它是第三章通向第四章的引桥，需要给出每个痛点在平台上落在哪个模块、完成到什么程度。若在合并时把 3.1／3.2 的实现细节补回去，会重新造成“理论章里讲实现”的断裂；反之，若把 3.3 的平台内容再抽走，则第三章与第四章之间会失去衔接。第五章的 5.1.1、5.4.1 引用 3.2.6 的原则属正常引用，不必改动。
